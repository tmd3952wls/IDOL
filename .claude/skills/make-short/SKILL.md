# make-short

연예인 이름 → 완성 mp4. 중간에 사용자에게 묻지 않고 끝까지 진행한다 (완전 자동이 사용자 결정).
AI 생성 이미지·영상은 쓰지 않는다. 업로드도 하지 않는다. 모든 명령은 프로젝트 루트에서 실행한다.

## 1. 소재 수집

```bash
python pipeline/collect.py "<이름>"
```

`work/<이름>/candidates.json`: 영상별로 댓글 타임스탬프가 몰린 순간과 그 순간의 실제 댓글.

## 2. 후보 미리보기 (반드시 직접 본다)

```bash
python pipeline/preview.py "<이름>"
```

점수 상위 18개 순간마다 `work/<이름>/preview/NN_<id>_<t>.jpg` 장면표(2초 간격 16칸, 칸마다 원본 영상의 초)와
장면 전환 시각(cuts), 인식된 대사가 나온다. **장면표를 Read로 열어 화면 자막과 인물을 확인한 뒤** 고른다.
댓글 타임스탬프만 믿고 고르면 주인공이 아닌 사람의 장면이 섞인다.

## 3. 구성안 작성 (`work/<이름>/plan.json`)

```json
{"name": "<이름>", "title": "[수식어]한 <이름>ㅋㅋ", "hint": "출연자 이름과 프로그램명 한 문장",
 "segments": [{"video": "<id>", "start": 434.2, "end": 460.8, "keyword": "떡빵국", "comment": "실제 댓글"}]}
```

- 구간 10~12개. 말하는 부분만 남기면 3분의 1로 줄어드니 원본 기준 25~30초씩 넉넉히 잡는다
  (장면표에서 내용을 확인한 범위 안에서). 완성 길이 목표 100~130초.
- 주인공이 실제로 웃기는 장면만. 첫 구간은 가장 강한 것.
- `keyword`: 상단 큰 제목(노란색), 2~5자, 화면 자막·대사에서 확인되는 말. 끝의 `;`는 렌더가 자동으로 붙인다.
- `comment`: 그 구간에서 처음 보여줄 **실제 댓글**(지어내지 않는다). 40자 이내. 이후에는 같은 원본 영상의
  인기 댓글이 좋아요 순으로 1.5초마다 자동으로 바뀐다(candidates.json에서 가져옴).
- `hint`: 음성 인식이 이름을 맞게 적는 데 쓰인다.
- 좌측 번호 목록은 쓰지 않는다(사용자가 뺐다).

## 4. 자막 초안 만들고 교정 (이 파일이 컷 편집도 결정한다)

```bash
python pipeline/render.py "work/<이름>/plan.json" --prepare
```

`work/<이름>/captions.json`에 구간별 자막 줄(`t0`, `t1`, `text`, `style`)이 생긴다. 시각은 음성 인식의 단어 타이밍
(쉬었다 나오는 말은 실제 소리가 올라오는 지점으로 보정됨)이라 **`t0`/`t1`은 건드리지 않고 `text`와 `style`만 고친다.**
**자막 줄이 남아 있는 부분만 영상에 남는다.** 줄을 지우면 그 부분의 영상도 잘린다.
- 인식 오류를 2단계 장면표의 방송 자막과 대조해 바로잡는다(이름, 비슷한 발음).
- 확신 없는 줄, 군더더기(진행 멘트, 반복)는 지운다 → 영상이 빨라진다.
- 인식이 놓친 핵심 대사나 말 없는 몸개그는 줄을 추가한다. 시각은 (원본 초 - start). 말이 아닌 장면은 `(웃참 실패)`처럼 괄호로.
  화면은 얼굴만 크게 잡히므로 발·소품 같은 것을 가리키는 설명은 쓰지 않는다.
- 한 줄 8자 안팎(말하는 순간에 뜨고 바로 사라진다).
- `style`: 일반 대사는 애니메이션 없이 색만 다르다 — `normal` 흰색 / `question` 하늘색 / `aside` 회색 작게(혼잣말·괄호 설명).
  **포인트가 되는 줄에만** 애니메이션 스타일을 쓴다(구간당 2~4줄) — `shout` 노랑 크게 쾅+흔들림(큰 소리·펀치라인) /
  `laugh` 분홍 통통(웃음·애교) / `point` 연두 쫙 펼쳐짐(핵심 단어).

## 5. 렌더

```bash
python pipeline/render.py "work/<이름>/plan.json"
```

자막이 있는 부분만 숨 쉴 틈 없이 이어 붙이고, 자막 한 줄마다 컷을 나눈다(한 마디 = 한 컷, 컷 평균 1초 안팎).
컷마다 가장 큰 얼굴을 찾아 크게 자르고 확대 정도를 번갈아 바꾼다. 자른 화면에 방송 문구(자막·태그·로고)가 걸치면
글자를 찾아 그 부분만 블러로 가린다. 글꼴은 전부 배민 주아.
`output/<이름>/<이름>.mp4`, `meta.txt`, `contact.jpg`가 나온다.
plan.json이나 captions.json을 고치고 다시 돌리면 바뀐 구간만 다시 만든다. "건너뜀"이 뜨면 한 번 더 실행한다.

## 6. 검수

contact.jpg(구간마다 2장)를 열어 확인: 방송 문구가 블러되지 않고 남았는지, 블러가 얼굴을 가리지 않는지, 얼굴이 제대로 잡혔는지(엉뚱한 사람·빈 화면), 자막 글자, 키워드와 내용의 일치.
어긋난 구간은 plan.json·captions.json을 고쳐 5단계 반복. 끝나면 길이·구간 수와 함께 확인하지 못한 부분
(소리는 들어보지 못함: 점프컷 지점의 말 끊김 등)을 그대로 보고한다.

## 참고

- 이 PC의 yt-dlp는 `--compat-options no-certifi`가 있어야 동작한다(스크립트에 반영됨).
- 레이아웃·자막 스타일·얼굴 크기 수치는 `pipeline/render.py` 상단 상수(바꾸면 STYLE_VERSION도 올린다). 공백 판정은 `pipeline/speech.py`.
- 파일 삭제 명령은 안전 검사에 막힐 수 있다. 캐시를 지울 필요 없이 다시 실행하면 된다.
